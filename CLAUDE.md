# followorbounce.github.io — Knowledge Network

Personal index/hub site: essays, interactive experiments, media-server tooling, visual/audio synthesizers, and reference dictionaries, served from GitHub Pages root. **Note:** earlier memory summarized this repo as just "design-divine-future-dictionaries" — it is much larger; the two dictionaries are one corner of a full personal site.

## Structure
- **Architectural rule: every page is a fully self-contained single `.html` file at repo root** (exception: the video-synth family lives in `visual-synths/`). `/assets/` holds `favicon.svg`, shared visual-synth-kit files, and `theme-toggle.js`. Respect this convention; don't introduce shared assets casually.
- **Unified theme toggle** (2026-09-26): `/assets/theme-toggle.js` is loaded (sync, in `<head>`) on every page. It reads `fb-theme` from localStorage (falls back to `prefers-color-scheme`), sets `data-theme` on `:root` before first paint, and injects a Light/Dark button into `header .wrap` (or `#chrome` for the node-based-development field-guide). The index's own toggle in `engine/cubes.js` still exists; `theme-toggle.js` skips injection if `#btn-theme` already exists, so they coexist. Every page must have matching `@media(prefers-color-scheme:dark){:root:not([data-theme="light"]){...}}` and `:root[data-theme="dark"]{...}` CSS blocks. Dark-by-default pages (Pulse Train family, Signal Chain, Heavy Machinery Blueprint) use `[data-theme="light"]` instead to provide a light alternative.
- `index.html` — the Knowledge Network hub/index. **Generated, not hand-edited** (since 2026-09-17): produced by `engine/build_network.py` from `engine/own-pages.json` (this repo's own pages) plus `aerospace/pages.json`, `Maya-Calendar/pages.json`, and `machinery/data/graph.json` (each sibling repo's own source of truth). To add/change an entry for this repo's own pages, edit `engine/own-pages.json`, then re-run `python3 engine/build_network.py` — don't hand-edit the generated `index.html` directly, it'll be overwritten on the next run. The pre-engine hand-maintained homepage has been removed (`old/index.html` deleted 2026-09-25).
- **Homepage "Latest art task" card** (2026-09-21): `engine/blog-feed.{css,html,js}` are inlined into the generated `index.html` by `build_network.py`. The JS fetches, on every page view, the newest post of the **Art tasks** category (slug `art-tasks`) of `designdivinefuture.wordpress.com` from the public WordPress.com REST API (CORS-open) — so it updates itself daily with no rebuild — and renders category / title / summary / terms chips / time limit / first image (letterboxed on a fixed mat, never cropped). Post text is parsed tolerantly (labels vary: `Design terms applied` / `Terms` / `Design Terms Used`; `Concept summary` / `Concept` / `Exercise:`); nothing from the API is inserted as HTML. Falls back to a plain link to the Art tasks archive if the API fails or times out (8 s) or JS is off. Edit those three files, not `index.html`.
- **Homepage header/hero** (updated 2026-09-25): header = "FOLLOW OR BOUNCE" brand chip on the left + cubes toggle button (▪) + dark/light theme toggle + compact search input on the right. `<title>` is "Follow or Bounce". The hero is only the eyebrow "Index · Dmitrii V · WH6HIS". The generator itself is still called the Knowledge Network Engine.
- **Falling cubes animation** (2026-09-25): `engine/cubes.{css,js}`, inlined by `build_network.py`. A canvas-based particle effect of semi-transparent pixelated falling cubes, toggled by the ▪ button in the header. Also contains the dark/light theme toggle logic (localStorage key `fb-theme`, respects `prefers-color-scheme` as default). Dark mode sets CSS vars on `:root[data-theme="dark"]` and overrides hardcoded light-mode colors in search-wrap. Dark mode custom properties for plugin cards (`--card-bg`, `--ink-body`, `--fig-bg`, `--skel-a`, `--skel-b`) are also defined here and used by blog-feed, calendar-window, and term-of-day CSS.
- **Homepage "What day is it" window** (2026-09-22): `engine/calendar-window.{css,html,js}`, inlined the same way as the art-task card and styled to match it (the art-task card no longer shows a date; this card keeps the dark date tile). Shows today in 8 calendars (Julian, Hebrew, Islamic tabular, Persian, Indian Saka, Ethiopian, Chinese zodiac, Maya) plus live Local/UTC/JDN/Unix. It does **not** copy calendar math: it loads World Calendar Explorer's own `js/core.js`, `calendars/*.js`, `registry.js` at runtime from `https://followorbounce.github.io/world-calendar-explorer/js/` and calls `Registry.computeAll`, so fixes there propagate here. Re-renders at local midnight; falls back to a link after 8 s or a script error. If WCE renames `Core`/`Registry` or a calendar `key`, this card breaks — keep them in sync.
- **Homepage "Term of the day" window** (2026-09-26): `engine/term-of-day.{css,html,js}`, inlined by `build_network.py`. Two 1/2-width cards side by side: "Emotion of the day" (from Dictionary of Inner Experience, 77 terms) and "Design term of the day" (from Dictionary of Design, 112 terms). Each shows name + SVG art + definition + link to the dictionary entry. Picks a deterministic daily term using a date-seeded hash; a shuffle button picks a random one. The full term data (including SVGs) is embedded in the JS — if either dictionary adds/removes terms, regenerate `term-of-day.js` by re-running the Python script that built it (`engine/build_network.py` does NOT auto-extract dictionary data; the JS file is a static snapshot).
- **Homepage "Generative · Interactive" canvas** (2026-09-26): `engine/gen-canvas.{css,html,js}`, inlined by `build_network.py`. A full-width interactive canvas below the Term of the Day cards. 6 modes, in bar order Lines (default, first screen), Grid, Scan, Matrix, Meadow, Mesh. **Grid** (added 2026-09-29, in the spirit of Nonotak — not affiliated): always a black stage with white light regardless of theme, a lattice of squares that cycle through four cross-faded 7 s movements (rotate / breathe / outlined diamonds / travelling bars) driven by a radial wave from the pointer; press-and-hold morphs squares into circles; no strobing. Lines/Scan/Matrix (since 2026-09-29, replacing Ripple/Drift/Weave) are 2D-canvas miniatures of the video-synth studies — **Lines** (Displacement Field: hidden-line terrain; pointer lifts, click ripples, opt-in **Mic** button = scrolling spectrogram; mic stops when leaving the mode or scrolling away), **Scan** (Photogrammetry Scan: lazily fetches `/visual-synths/data/city-scan.bin` only when picked, uses the first 26k points, pointer orbits, press-and-hold scatters points randomly; procedural towers if the fetch fails — keep in sync with the SFM1 layout), **Matrix** (Data Matrix, softened: hairline barcodes, sparse dots, waveform, hex strip at ~50 % ink with gaps and gliding between ticks; pointer x = tempo 0.6–3 Hz, hold highlights the band under the pointer with a faint tint). Each mode has a one-line hint overlaid in the frame (`#gen-hint`) and at most one option button (`#gen-opts`, only Mic). Kept deliberately to two interactions per mode. Palette adapts to light/dark theme. Only animates while in viewport (IntersectionObserver). No external dependencies.
- **Homepage "Open data" dashboard** (2026-09-26): `engine/open-data.{css,html,js}`, inlined by `build_network.py`. Eight-cell live dashboard: Earthquakes (USGS 24h M1+ feed), Aircraft (OpenSky Network), Ships (no CORS API — shows "—"), Volcanic activity (NASA EONET), Wildfires (NASA EONET), Wave height (Open-Meteo Marine, N Atlantic), Solar wind (NOAA SWPC), Satellites (no CORS API — shows "—"). Auto-refreshes every 5 min; manual Refresh button. Each cell links to its data source. Gracefully falls back to "—" on CORS/fetch failures. 4×2 grid, collapses to 2-column on mobile.
- **Homepage "Audio synth · live" plugin** (2026-09-29): `engine/live-synth.{css,html,js}`, inlined by `build_network.py` directly under Open data. Four nodes in a line inside the frame — 01 Pulse (16-step tappable pattern, tempo, Sine/Click/Tone voice, Dice) → 02 Filter (LP/BP/HP, cutoff, resonance, bar-synced LFO) → 03 Drive (tanh + bit-crush waveshaper, mix) → 04 Space (tempo-synced delay 1/16–1/4, feedback ≤ 0.85, mix, hold-to-freeze) — and the OUT node outside the frame (Play, meter, volume), joined by a cable that crosses the frame border (vertical below the frame at ≤ 980 px; 2×2 nodes on phones). Every node: bypass footswitch (click-free wet/dry crossfade) and a scope that doubles as an XY pad for its two main params. Keys (only while focus is inside the section): Space play, 1–4 bypass, D dice, hold F freeze. Safety: compressor limiter, then a half-level tanh soft-clip ceiling (output ≤ 0.93; worst case measured 0.922). AudioContext is created on first Play; playback stops when the tab is hidden. Under it: links to `/audio-synths/` and the Node Database.
- **Audio Synths hub** `audio-synths/index.html` (2026-09-29, hand-maintained, same chrome as the Video Synths hub): SoundOS (**Desktop only** badge), Pulse Train — Stage II (**Mobile & desktop**), Node Database, the homepage Live rig, and an archive list (Pulse Train family also tagged Mobile & desktop). The **Audio Synth category is hidden on the index** (`"hidden": true` in `own-pages.json`, hub entry `audio-synths` added), reached from the link under the live plugin — same pattern as Video Synths.
- `archive.html` — **generated** by `build_network.py`. Lists pages marked `"archived": true` in `engine/own-pages.json`. Linked from the index footer. To archive a page, add `"archived": true` to its entry in `own-pages.json` and rebuild.

Indexes all four repos' content; does not regenerate aerospace's or Maya-Calendar's individual articles (see `ROADMAP-2.md` §8 for that open Phase 2 scope).

They share an identical inline chrome + tiny WebGL kit (`const GL = {...}`: program/persp/lookAt/orbit camera/fit/slider/seg/visibleLoop + shared GLSL noise and cosine palette). Stage is always black (gallery wall); page chrome follows the theme. Each page has a How it works / Lineage (reference artists, "not affiliated") / Limits section — keep those honest if behaviour changes. Camera/mic start only when their source is picked; Data Matrix flash is off by default, ≤3 Hz, and disabled under reduced motion.
  - **Photogrammetry Scan data pipeline**: the only study that loads data. `visual-synths/data/city-scan.bin` (2 MB, "SFM1" layout: int16 positions + uint8 colour + 251 camera poses) is generated from the raw AliceVision/Meshroom Alembic export `visual-synths/abc/cloud_and_poses.abc` (8.5 MB, **gitignored** — keep it locally, it is the source) by `python3 visual-synths/tools/abc_to_bin.py visual-synths/abc/cloud_and_poses.abc visual-synths/data/city-scan.bin` (needs numpy; uses the dependency-free Ogawa reader `tools/abc_reader.py`). The page also carries a JS port of that reader (`const Scan`) so visitors can drop their own `.abc` / `.ply`; if you change one reader, change the other (they were checked to give identical values). Up = mean solved camera up; cameras are ordered by the `pngExport_NNNNN` frame number in their names (that is the capture path). Decompose has a type switch (`P.decompType` / `uDecompType`): **Front** (default, the original Point Cloud Scan edge-first sweep along x with noise wind; Solid discards eroded points) and **Scatter** (random per-point release with a wide 30 % smoothstep window, eased sine arc, then a slow 1:2:3 harmonic orbit around a random home in the 1–99 % box `uBZ`; 100 % = uniform breathing cloud). The bundled scan's provenance is unknown (a sample file; its path pointed at a Qiita author's desktop, names suggest rendered aerial footage) — the page says so in its Data section; don't claim authorship or a source for it.

To verify output, make a scratch copy with `preserveDrawingBuffer:true`, call `frame()` synchronously a few (or a few hundred) times, `gl.readPixels` and paint the result into a 2D canvas/banner before load finishes — that was done for all four studies on 2026-09-29.
