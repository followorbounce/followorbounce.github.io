# followorbounce.github.io — Knowledge Network

Personal index/hub site: essays, interactive experiments, media-server tooling, visual/audio synthesizers, and reference dictionaries, served from GitHub Pages root. **Note:** earlier memory summarized this repo as just "design-divine-future-dictionaries" — it is much larger; the two dictionaries are one corner of a full personal site.

## Structure
- **Architectural rule: every page is a fully self-contained single `.html` file at repo root** (exception: the video-synth family lives in `visual-synths/`). `/assets/` holds `favicon.svg`, shared visual-synth-kit files, and `theme-toggle.js`. Respect this convention; don't introduce shared assets casually.
- **Unified theme toggle** (2026-09-26): `/assets/theme-toggle.js` is loaded (sync, in `<head>`) on every page. It reads `fb-theme` from localStorage (falls back to `prefers-color-scheme`), sets `data-theme` on `:root` before first paint, and injects a Light/Dark button into `header .wrap` (or `#chrome` for the node-based-development field-guide). The index's own toggle in `engine/cubes.js` still exists; `theme-toggle.js` skips injection if `#btn-theme` already exists, so they coexist. Every page must have matching `@media(prefers-color-scheme:dark){:root:not([data-theme="light"]){...}}` and `:root[data-theme="dark"]{...}` CSS blocks. Dark-by-default pages (Pulse Train family, Signal Chain, Heavy Machinery Blueprint) use `[data-theme="light"]` instead to provide a light alternative.
- **Dark-mode helpers for legacy literals** (2026-10-02): essay pages that paint canvases call `themeColor('--token', '#literal')` (defined inline right after the theme-toggle `<script>`; returns the literal in light mode). Hardcoded light CSS colours are written `var(--dk-<hex>, #<hex>)` with `--dk-*` defined only in the two dark blocks. Use the CSS tokens directly in new code instead.
- `index.html` — the Knowledge Network hub/index. **Generated, not hand-edited** (since 2026-09-17): produced by `engine/build_network.py` from `engine/own-pages.json` (this repo's own pages) plus `aerospace/pages.json`, `Maya-Calendar/pages.json`, and `machinery/data/graph.json` (each sibling repo's own source of truth). To add/change an entry for this repo's own pages, edit `engine/own-pages.json`, then re-run `python3 engine/build_network.py` — don't hand-edit the generated `index.html` directly, it'll be overwritten on the next run. The pre-engine hand-maintained homepage has been removed (`old/index.html` deleted 2026-09-25).
- **Homepage "Latest art task" card** (2026-09-21): `engine/blog-feed.{css,html,js}` are inlined into the generated `index.html` by `build_network.py`. The JS fetches, on every page view, the newest post of the **Art tasks** category (slug `art-tasks`) of `designdivinefuture.wordpress.com` from the public WordPress.com REST API (CORS-open) — so it updates itself daily with no rebuild — and renders category / title / summary / terms chips / time limit / first image (letterboxed on a fixed mat, never cropped). Post text is parsed tolerantly (labels vary: `Design terms applied` / `Terms` / `Design Terms Used`; `Concept summary` / `Concept` / `Exercise:`); nothing from the API is inserted as HTML. Falls back to a plain link to the Art tasks archive if the API fails or times out (8 s) or JS is off. Edit those three files, not `index.html`.

Checked no horizontal overflow at 320/375/390.

The hero is only the eyebrow "Index · Dmitrii V · WH6HIS". The generator itself is still called the Knowledge Network Engine.

Also contains the dark/light theme toggle logic (localStorage key `fb-theme`, respects `prefers-color-scheme` as default). - **Homepage "What day is it" window** (2026-09-22): `engine/calendar-window.{css,html,js}`, inlined the same way as the art-task card and styled to match it (the art-task card no longer shows a date; this card keeps the dark date tile). Shows today in 8 calendars (Julian, Hebrew, Islamic tabular, Persian, Indian Saka, Ethiopian, Chinese zodiac, Maya) plus live Local/UTC/JDN/Unix. It does **not** copy calendar math: it loads World Calendar Explorer's own `js/core.js`, `calendars/*.js`, `registry.js` at runtime from `https://followorbounce.github.io/world-calendar-explorer/js/` and calls `Registry.computeAll`, so fixes there propagate here. Re-renders at local midnight; falls back to a link after 8 s or a script error. If WCE renames `Core`/`Registry` or a calendar `key`, this card breaks — keep them in sync.
- **Homepage "Term of the day" window** (2026-09-26): `engine/term-of-day.{css,html,js}`, inlined by `build_network.py`. Two 1/2-width cards side by side: "Emotion of the day" (from Dictionary of Inner Experience, 77 terms) and "Design term of the day" (from Dictionary of Design, 112 terms). The full term data (including SVGs) is embedded in the JS — if either dictionary adds/removes terms, regenerate `term-of-day.js` by re-running the Python script that built it (`engine/build_network.py` does NOT auto-extract dictionary data; the JS file is a static snapshot).
- **Homepage "Generative · Interactive" canvas** (2026-09-26): `engine/gen-canvas.{css,html,js}`, inlined by `build_network.py`. A full-width interactive canvas below the Term of the Day cards. 6 modes, in bar order Lines (default, first screen), Grid, Scan, Matrix, Meadow, Mesh. **Grid** (added 2026-09-29, in the spirit of Nonotak — not affiliated): always a black stage with white light regardless of theme, a lattice of squares that cycle through four cross-faded 7 s movements (rotate / breathe / outlined diamonds / travelling bars) driven by a radial wave from the pointer; press-and-hold morphs squares into circles; no strobing. Lines/Scan/Matrix (since 2026-09-29, replacing Ripple/Drift/Weave) are 2D-canvas miniatures of the video-synth studies — **Lines** (Displacement Field: hidden-line terrain; pointer lifts, click ripples, opt-in **Mic** button = scrolling spectrogram; mic stops when leaving the mode or scrolling away), **Scan** (Photogrammetry Scan: lazily fetches `/visual-synths/data/city-scan.bin` only when picked, uses the first 70k points drawn as fine 1-css-px dots at ~42 % ink, pointer orbits, press-and-hold scatters points randomly; procedural towers if the fetch fails — keep in sync with the SFM1 layout), **Matrix** (Data Matrix, softened: hairline barcodes, sparse dots, waveform, hex strip at ~50 % ink with gaps and gliding between ticks; pointer x = tempo 0.6–3 Hz, hold highlights the band under the pointer with a faint tint). **Meadow** (rebuilt 2026-10-02 as WebGL2, "Dreaming Meadow"; the old 2D meadow `flowInit/flowDraw` stays as the fallback when WebGL2 is missing or the context is lost): a second canvas `canvas.gen-gl` is inserted over `#gen-cv` only for this mode (pointer listeners are therefore on the frame, not the canvas). ~2.6–9.5k instanced grass blades (count scales with canvas area; sorted far→near so blending layers correctly) bend with tip-weighted stiffness under prevailing wind + travelling gusts (`bendAt` in `GL_COMMON`, shared by blades and flowers so heads stay on their stems); the pointer leaves a 16-point wake (grass parts and recovers over ~2.6 s), press = expanding gust ring. Flowers are SDF sprites in drifts, sized by depth, iridescent (`pal`), open by day / close and glow at night, heads lean toward the sun. A slow pigment field (`pal2`, computed per vertex) sweeps colour through the grass; the sky shader has domain-warped pigment clouds, stars, a sun with bloom and the moon drawn in **today's real phase** (synodic month from 2000-01-06). **Sky clock:** sun on a 24 h arc (rises 06:00 left, noon overhead, sets 18:00 right), moon offset by its phase; default "dream time" starts at the visitor's local time and runs one day per `DREAM_DAY` = 120 s; the mode's option button "Your time" pins it to the real clock (forced under reduced motion). Sky colours follow the sun's height; light/dark theme sets the palette. The hint shows the sky time. Test hook: `window.__genPreserve=true` before the script makes the GL canvas preserve its buffer and exposes `window.__meadow` / `window.__meadowDraw(t)` for read-back tests (headless screenshots capture WebGL as black). Each mode has a one-line hint overlaid in the frame (`#gen-hint`) and at most one option button (`#gen-opts`: Mic for Lines, Your time for Meadow). Kept deliberately to two interactions per mode. Palette adapts to light/dark theme. Only animates while in viewport (IntersectionObserver). No external dependencies.
- **Homepage "Open data" dashboard** (2026-09-26; data sources fixed 2026-10-02): `engine/open-data.{css,html,js}`, inlined by `build_network.py`. Eight cells. **Direct from the browser** (APIs send `Access-Control-Allow-Origin: *`): Earthquakes (USGS 24 h M1+), Volcanic activity + Wildfires (NASA EONET), Wave height (Open-Meteo Marine, N Atlantic), Solar activity (NOAA SWPC `products/summary/solar-wind-speed.json` → `[{proton_speed}]` — the old `WindSpeed` field no longer exists — plus the latest planetary Kp from `noaa-planetary-k-index.json`), ISS live position (wheretheiss.at, shown on the Satellites cell). **Via the relay** `workers/open-data` (Cloudflare Worker `fob-open-data`, `https://fob-open-data.followorbounce.workers.dev/summary`, KV `OPEN_DATA`): Aircraft (OpenSky `states/all` — OpenSky only allows its own origin and refuses Cloudflare's network, so **`.github/workflows/opensky-relay.yml` fetches it every 30 min on GitHub's runners and POSTs just the count to `/ingest`** with the `OPEN_DATA_KEY` repo secret = Worker secret `REFRESH_KEY`; 192 of OpenSky's 400 anonymous daily credits), Ships (Fintraffic Digitraffic Baltic AIS, Worker cron every 20 min), Satellites (CelesTrak `GROUP=active`, Worker every ~2 h — CelesTrak allows one download per IP per 2 h). The Worker keeps the last good value per source and lists failures in `errors`. Cells show "as of HH:MM" and "—" when data is older than 3 h (12 h for satellites). Refreshes every 5 min + manual Refresh. Workflow files must be pushed over SSH (the HTTPS token lacks `workflow` scope). The refresh/ingest key's local copy is `~/.config/followorbounce/open-data-refresh-key`.
- **Homepage "Audio synth · live" plugin** (2026-09-29): `engine/live-synth.{css,html,js}`, inlined by `build_network.py` directly under Open data. Four nodes in a line inside the frame — 01 Pulse (16-step tappable pattern, tempo, Sine/Click/Tone voice, Dice) → 02 Filter (LP/BP/HP, cutoff, resonance, bar-synced LFO) → 03 Drive (tanh + bit-crush waveshaper, mix) → 04 Space (tempo-synced delay 1/16–1/4, feedback ≤ 0.85, mix, hold-to-freeze) — and the OUT node outside the frame (Play, meter, volume), joined by a cable that crosses the frame border (vertical below the frame at ≤ 980 px; 2×2 nodes on phones). Every node: bypass footswitch (click-free wet/dry crossfade) and a scope that doubles as an XY pad for its two main params. Keys (only while focus is inside the section): Space play, 1–4 bypass, D dice, hold F freeze. Safety: compressor limiter, then a half-level tanh soft-clip ceiling (output ≤ 0.93; worst case measured 0.922). AudioContext is created on first Play; playback stops when the tab is hidden. **iOS:** Play runs the same unlock as Pulse Train inside the tap — `navigator.audioSession.type='playback'`, a hidden looping silent `<audio playsinline>` (paused on Stop), and a one-sample buffer — otherwise the Ring/Silent switch mutes Web Audio on iPhone. Any new sound-making page needs this too. Under it: links to `/audio-synths/` and the Node Database.
